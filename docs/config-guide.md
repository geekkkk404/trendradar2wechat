# 配置指南（个性化你的 TrendRadar）

> 适用于本仓库一键脚本部署的 TrendRadar（原生部署，安装目录默认 `/opt/TrendRadar`）。
> 部署后的个性化（追什么词、推送节奏、信息源取舍）都在这里完成。
> 微信端可视化配置已在路线图中（v0.3 规划）；当前版本通过编辑配置文件实现，本文带你走通。

## 你的配置在哪：三个文件

| 文件 | 管什么 | 改动频率 |
|---|---|---|
| `/opt/TrendRadar/user-config/frequency_words.txt` | **关注关键词**：追什么词、排除什么词、每组显示几条 | 最常改 |
| `/opt/TrendRadar/user-config/config.yaml` | **主配置**：推送节奏、信息源、报告形态、AI 开关等（上游自带全中文注释，24KB 逐项可读） | 偶尔改 |
| `/opt/TrendRadar/trendradar.env` | **渠道凭证**：微信桥接线、企业微信/飞书/钉钉/Telegram 凭证、AI key、网页端口 | 一般不动 |

**为什么放 `user-config/`？**——这是安装脚本为你开辟的专属目录，与上游源码隔离。
**升级 / 重跑安装脚本时，你的配置永远不会被覆盖**（脚本只在目录为空时从上游模板播种一次）。

想恢复出厂配置：删除 `user-config/` 里的对应文件，重跑安装脚本即可重新播种。

## 改完怎么生效

- 定时抓取每 30 分钟一轮，**每轮都重新读取全部配置**——改完最多等半个周期自动生效；
- 想立即验证：`systemctl start trendradar-fetch`（手动触发一轮抓取，微信端马上能收到新样式的推送）；
- 网页报告是静态文件服务，改配置无需重启它；
- 端口、安装形态（`--no-web` / `--with-mcp` 等）属于安装期选项，重跑安装脚本传对应参数即可（幂等，配置与数据保留）。

## 关键词怎么写（frequency_words.txt）

规则来自上游模板（文件内有完整的中文教学注释，此处是精要）。整个文件分两大区块：

```
[GLOBAL_FILTER]        ← 全局过滤区：下面列的词，命中即从推送中排除
震惊

[WORD_GROUPS]          ← 词组定义区：你想追的关键词，词组之间空行分隔
```

常用语法（每行一条）：

| 写法 | 含义 | 示例 |
|---|---|---|
| `词` | 标题包含即命中 | `华为` |
| `词 => 别名` | 命中后显示为别名 | `胖东来 => 胖东来` |
| `/正则/ => 别名` | 正则匹配（忽略大小写） | `/胖东来\|于东来/ => 胖东来` |
| `[组名]` | 词组首行起一个组名 | `[苹果公司]` |
| `+词` | 必须词：组内所有必须词都命中才算命中 | `+发布` |
| `!词` | 组内排除：仅排除当前词组的匹配 | `!水果` |
| `@数字` | 限制该词组最多显示几条 | `@5` |
| `#` 开头 | 注释，不生效 | `# 过滤标题党` |

一个完整词组示例（上游原文）：

```
[苹果公司]
苹果
!水果
```

不写任何关键词时，推送的是各平台热榜全量内容；写了关键词，则只推送命中你词组的内容。

## 主配置常用项（config.yaml）

打开 `user-config/config.yaml`，每项都有上游的中文注释。普通读者最常动的几处：

| 想要什么 | 改哪里 |
|---|---|
| 只在早晚各推一次 / 仅办公时间推送 / 夜猫时段 | `schedule.preset`（自带模板：`always_on` / `morning_evening` / `office_hours` / `night_owl` / `custom`） |
| 增减抓取的热榜平台 | `platforms.sources`（每项带 `enabled` 开关） |
| 增减 RSS 订阅源 | `rss` 区块（自带 hacker-news、阮一峰、yahoo-finance 等） |
| 推送内容形态（每日汇总 / 实时 / 增量） | `report.mode`（`daily` / `current` / `incremental`） |
| 报告按关键词还是按平台分组展示 | `report.display_mode` |
| 开关 AI 分析/翻译 | `ai_analysis.enabled` / `ai_translation.enabled`（需先在安装时配 `--ai-key`） |

其余高级项（存储后端、爬虫代理、权重排序等）默认值已经很合理，不必碰；想研究就看文件内注释。

## 故障排查

```bash
journalctl -u trendradar-fetch -n 50     # 抓取/推送日志（跟踪用 -f）
journalctl -u trendradar-web   -n 20     # 网页报告日志
systemctl list-timers trendradar-fetch*  # 确认定时任务在排程
```

- 抓取偶尔失败（数据源抖动）属正常，下一轮自动重试；
- 改配置后没生效：先确认改的是 `user-config/` 下的文件，再手动 `systemctl start trendradar-fetch` 触发一轮看日志；
- 任何情况下重跑安装脚本都是安全的（幂等），它会补齐服务、更新源码，但不动你的 `user-config/`。
